# 从研究原型到马来西亚前线试点

## 第一阶段：一个可验证的地区

建议先以 Selangor 一个洪灾高风险地区做试点，或与 SJAM / 大学导师确认可获取历史资料的地区。需要逐事件雨量 / 水位、道路关闭与重开时刻、PPS 开放与真实可用容量、汇总人口、匿名化资源任务与到达时间。

研究问题可定为：**在道路中断与需求不确定下，如何减少仍未获得可行安置 / 救援服务的弱势人口，并提高有限车队的覆盖？** 先验证一个灾种一个地区，比未验证地覆盖全国更容易形成可靠 FYP。

数据完成前，当前虚构场景继续用来测试算法；不把实时网页统计直接作为地面事实。与前线合作的重点是通道怎么确认、资料多久过期、谁能批准方案、断网时怎么更新。

## 第二阶段：把静态分配变成运输计划

引入 OR-Tools 的时窗、车辆容量、异质车队、上车 / 救助时间、返程与燃料约束，连接车辆到社区再到 PPS 的完整行程。把救援人员、巴士座位、轮椅位、医疗能力、物资重量与仓储区分开。

以时变道路和共享道路通量形成时间展开网络；比较最短路、贪心分配和联合优化。输出每项资源的明确出发、到达、服务、转运与再出发时刻，报告求解时限和最优性间隙。

## 第三阶段：验证预测与不确定性

用真实历史事件建立 PA 模型。训练、验证、测试按事件和时间分离；再做地区留出。评价不止准确率，还包括 Brier、校准、PR-AUC、严重漏报、信息延迟和具体调度政策下的未服务人数。

用真实观测估计 Markov / semi-Markov 转移与道路共同失效，比较鲁棒优化、两阶段随机规划和滚动时域重规划。灾难强度不确定、资料本身不确定和算法不确定要分别记录。

## 第四阶段：前线工作方式

与机构做桌面演练：谁收集通道报告、谁确认 PPS、多久更新、何时停止采用旧路线。加入角色权限、审批、审计、现场回传、撤销与离线缓存。手机只展示经过批准且有有效时限的任务。

只有真实数据、正确约束、独立验证和实际演练共同通过后，才讨论业务试点。当前原型没有对外发警报或调派任何资源。

## 多灾种扩展

| 灾种 | 需新增或替换的危险度层 | 特殊调度约束 |
|---|---|---|
| 洪灾 | 水深 / 流速 / 时变淹没、桥梁与通行观测 | 道路与船艇不同图、可用登陆点 |
| 滑坡 | 地形、地质、降雨阈值、坍塌足迹 | 隔离道路、二次滑坡禁入、重型装备 |
| 地震 | 震动、建筑损伤、余震与桥梁检查 | 城搜队、医疗转运、生命线损毁 |
| 海啸 | 到达时间、淹没区与垂直避难 | 严格到达时限、步行能力、垂直容量 |
| 危化事件 | 物质、风场、地形和浓度扩散 | 上风 / 侧风撤离、隔离区、特定防护能力 |

这些是架构扩展方向，不是已完成的模型。
